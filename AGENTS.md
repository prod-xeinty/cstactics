## 1. Что мы делаем

Сайт с тактиками для **Counter-Strike 2**: готовые раунды от «заколил за 10 секунд во фризтайме» до полного разбора с гранатами. Тактики для дуо, тройки и полного стака, а ещё клатч-ситуации.

**Чем отличаемся от сайтов с раскидками:** продаём не лайнапы, а **готовый раунд как сценарий**: роли, гранаты, тайминги, что делать если пошло не так. Оценки тактик разбиты по уровням FACEIT, поэтому видно, что заходит именно на твоём уровне.

**Цель проекта:** пассивный доход (реклама / партнёрки / премиум — модель монетизации пока не выбрана).

**Сейчас:** только карта **Dust2**. Остальные карты — после того как Dust2 сделан хорошо.

## 3. Экраны и функции (MVP)

### 3.1 Плашка обновления игры
- Показывается вверху при входе, если вышел новый патч CS2 после версии, на которой проверены тактики.
- Текст на сленге: «Вышла обнова CS2 [дата]. Раскидки могут лететь не туда — чекайте гранаты в оффлайне перед каткой».
- Закрывается крестиком (запоминаем в localStorage до следующего патча).
- Каждая тактика хранит версию игры, на которой её проверили. Метка на карточке: «Чекнуто на новом патче» (зелёная) / «Не чекали после обновы» (оранжевая).

### 3.2 Главная
1. Навигация: логотип, «Тактики», «Под твоё эло», кнопка «+ Своя тактика», справа «Войти через Steam» или профиль (ник · FACEIT лвл · эло · Выйти).
2. **Карусель на весь экран** с топ-тактиками: карта, сторона, состав, экономика, сложность, быстрая версия (до 4 строк), панель оценок по трём шкалам FACEIT. Стрелки + точки.
3. Каталог тактик Dust2 с фильтрами: сторона (все / T / CT), состав (любой / дуо / тройка / фулл стак), «оценки и сортировка для» (лоу / мид / хай). Сортировка по оценке выбранной шкалы.
4. Клатчи — карточки ситуаций.
5. Баннер «Есть своя тактика?» → анкета.
6. «Как работает оценка» — 3 шага.

### 3.3 Окно после логина и экран «Под твоё эло»
- После входа через Steam сервер находит FACEIT-профиль и показывает модалку: «Нашли твой FACEIT: N лвл, M эло» → кнопка «Показать тактики под меня».
- Экран «Под твоё эло»: заголовок «Тактики для N лвл», блок **«Заходят на твоём уровне»** (оценка своей шкалы ≥ 4.0 и голосов ≥ 5, по убыванию) и блок **«Пока не заходят или мало голосов»**. На каждой карточке строка «Лоу x · Мид y · Хай z» для сравнения.
- Не залогинен → экран-приглашение войти.
- Позже можно сделать выборку точнее, чем три шкалы (например, голоса игроков в окне ±150 эло от твоего), когда голосов станет много.

### 3.4 Анкета «Своя тактика»
Только для залогиненных. Поля повторяют шаблон карточки (раздел 4):
1. **Основное:** название*, карта (сейчас только Dust2), сторона, состав (2/3/4/5), экономика, сложность (1–3), версия игры, чекбокс «роли зависят от спавна», колл (одна фраза).
2. **Быстрая версия:** 3 строки, можно добавить до 4.
3. **Роли по спавну:** строки «спавн (из словарика) · роль · гранаты», до 5; поле «если на нужном спавне никого».
4. **Гранаты:** строки «кто · что (смок/флешка/молик/хаешка/декой) · куда · когда (триггер) · зачем», до 12.
5. **Разбор:** если пошло не так, пост-плант, чем контрят.
6. **Видео:** один файл, **mp4 или webm, до 10 МБ** (подсказка: 20–30 сек в 720p).
- Проверка размера и типа **и на клиенте, и на сервере** (клиенту не доверяем).
- После отправки → статус «на проверке». Авторы проверяют в игре, потом тактика появляется в каталоге с меткой «от игрока» и ником автора.

## 4. Шаблон карточки тактики

```
Название
Карта | Сторона T/CT | Состав дуо/3/4/5 | Экономика эко/форс/фулл бай/любая | Сложность 1–3
Зависит от спавна: да/нет | Версия игры | Нужно гранат
Колл: одна фраза, включая распределение по спавну
Быстрая версия: до 4 строк
Роли по спавну: спавн → роль → гранаты; запасной вариант; фиксированные роли
Гранаты: кто → что → куда → откуда (примерно) → когда (триггер) → зачем
Ход раунда
Если пошло не так
Пост-плант
Чем контрят
Оценка: ставят игроки, отдельно по уровням FACEIT
```

**Клатч-ситуация:** `1vX · где бомба · сторона`, где ты, коротко (главная идея), где встать, что слушать, граната на дефьюз/заход, главная ошибка.

### Правила контента (обязательные)
1. Быстрая версия обязательна, не длиннее 4 строк.
2. Роли назначаются **по спавну, а не по нику**. Если роль требует конкретного человека — пометка «фиксированная».
3. Для каждой роли есть запасной вариант.
4. Гранаты — **словами, без лайнапов**: что → куда → по какому триггеру → зачем.
5. Триггер привязан к действию («после того как смок на крест встал»), секунды — только для старта раунда.
6. Названия точек и спавнов — **только из словарика** (раздел 5).
7. Каждая тактика проверяется в игре до публикации; хранится версия игры.
8. Пишем **на сленге, как в войсе**: «закидываем смок на крест», «если лонг не отдают — ротаемся на Б». Без канцелярита. Это касается и UI-текстов.

## 6. Система оценки

- Оценивать могут только залогиненные через **Steam OpenID**.
- По Steam ID сервер ищет профиль через **FACEIT Data API** и берёт уровень и эло. **API-ключ FACEIT только на сервере**, никогда в клиентском коде.
- Голос попадает в шкалу текущего уровня игрока:

| Шкала | Уровни FACEIT |
|---|---|
| Лоу | 1–3 |
| Мид | 4–7 |
| Хай | 8–10 |
| Без FACEIT | нет профиля — отдельная шкала, на основную не влияет |

- Что оцениваем (1–5): **«Работает»** (насколько выносит раунд) и **«Легко зайти»** (насколько просто отыграть).
- Один голос на аккаунт за тактику, можно менять.
- Уровень и эло перепроверяем раз в несколько дней; если игрок сменил шкалу — его голос переезжает.
- Шкала показывает оценку только при **≥ 5 голосах**, иначе «мало голосов».

## 8. Стек (утверждён)

- **Фронт + сервер:** Next.js (App Router) + React + TypeScript, запуск на Cloudflare Workers через vinext.
- **БД:** Cloudflare D1 + Drizzle ORM и явные SQL-миграции.
- **Файлы:** Cloudflare R2; новые видео приватные до прохождения модерации.
- **Фоновые задачи:** Cloudflare Queues.
- **Rate limit:** Durable Objects.
- **Защита публичных форм:** Cloudflare Turnstile.
- **Авторизация:** Steam OpenID 2.0 → собственная серверная сессия в защищённой cookie.
- **Валидация:** Zod на клиенте и сервере.
- **Тесты:** Vitest, Cloudflare Vitest Plugin и Playwright.
- **Деплой:** GitHub Actions + Wrangler.
- **Стили:** CSS-переменные и CSS Modules; визуальные правила и токены описаны в `DESIGN.md`.

Подробная архитектура: `docs/superpowers/specs/2026-10-19-cloudflare-architecture-design.md`.
Если меняешь стек — сначала запиши решение в «Журнал решений».

## 9. Дизайн

Основная дизайн-система — светлый **«Блокнот тактик»**: редакционная сетка, бумажная фактура, схемы и пометки тренера. Бордовый «Матч-центр» хранится только как резервное направление и не смешивается с основным интерфейсом.

Базовые токены:

| Токен | Значение |
|---|---|
| фон бумаги | `#F3EFE4` |
| светлая поверхность | `#FBF8F0` |
| основной текст / чернила | `#17243A` |
| второстепенный текст | `#5F6670` |
| линия | `#C9C3B7` |
| красная пометка / маршрут | `#B64232` |
| горчичный акцент / CTA | `#E8B84B` |
| проверено | `#2F7D5B` |
| предупреждение | `#9A5A20` |
| ошибка | `#B42318` |

Шрифты с кириллицей: **Oswald** 600/700 — заголовки и номера; **Golos Text** — основной текст; **JetBrains Mono** — тайминги и технические метки. В интерфейсе одновременно используем не более двух семейств; моноширинный шрифт подключаем только на экранах, где тайминги действительно важны.

Без градиентов, стекломорфизма, неона, эмодзи и декоративной «киберспортивности». Кнопки и интерактив — минимум 44 px по высоте. Контраст — WCAG 2.2 AA. Вёрстка обязана работать на телефоне. Полные правила: `DESIGN.md`.

## 10. Как работаем вдвоём (Claude + Codex)

- **Репозиторий один**, оба — коллабораторы. `main` защищён, всё через ветки и PR.
- **Ветки:** `feat/<что>`, `fix/<что>`. Один PR — одна фича.
- **Зоны** (предложение, поменяйте под себя):
  - Автор 1 + Claude — дизайн, фронт, контент тактик, словарик, тексты.
  - Автор 2 + Codex — бэкенд: Steam-логин, FACEIT API, БД, загрузка видео, модерация.
- **Ревью крест-накрест:** PR, написанный с Codex, ревьюит Claude, и наоборот.
- **Задачи** — в GitHub Issues. В PR ссылка на issue.
- **Решения** — сразу в раздел 12 этого файла (дата, что решили, почему).
- **Секреты** — только в `.env.local` (в `.gitignore`) и в настройках хостинга. Пример — в `.env.example` без значений.

## 11. Правила для агента

1. Отвечай и пиши комментарии, UI-тексты и коммиты **на русском**; UI — на сленге (раздел 4, правило 8).
2. Перед изменениями кратко опиши план и список файлов, которые тронешь.
3. Не придумывай коллауты, цифры оценок и «факты» о механике CS2 — бери из этого файла или спроси.
4. Не клади API-ключи и токены в код и коммиты.
5. Видео: проверка типа (mp4/webm) и размера (≤ 10 МБ) на клиенте **и** на сервере.
6. Пользовательский контент (тактики из анкеты) — недоверенный ввод: экранировать, не рендерить как HTML, статус `pending` до модерации.
7. Новое решение по продукту или стеку → запиши в раздел 12.
8. Держи этот файл короче 32 КБ (лимит Codex по умолчанию). Подробности — в `docs/`.
