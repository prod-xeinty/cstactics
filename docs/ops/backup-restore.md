# Бэкапы базы и восстановление (#25)

Два слоя защиты данных D1 (игроки, сессии, позже — тактики и голоса).

| Слой | Что | Глубина | Когда нужен |
|---|---|---|---|
| **Time Travel** | встроен в D1, всегда включён, бесплатно | **7 дней** (бесплатный тариф), с точностью до минуты | откатить ошибку: кривая миграция, удалили не то |
| **Ежедневный бэкап** | workflow «Бэкап D1», зашифрованный файл в артефактах GitHub Actions | **30 дней** (по одному на сутки) | пропала сама база / нужен откат дальше недели |

Видео (R2) — отдельной задачей, когда появится хранилище (#12).

## Как устроен ежедневный бэкап

`.github/workflows/backup.yml`, каждый день в 03:41 МСК (и вручную: Actions → «Бэкап D1» → Run workflow):

1. `wrangler d1 export --no-data` и `--no-schema` — **схема и данные отдельно**. Полная выгрузка D1 одним файлом идёт по таблицам в алфавитном порядке, и в пустую базу её **не восстановить**: строки `sessions` вставляются раньше, чем создана `users`. Мы склеиваем: сначала вся схема, потом все данные.
2. **Проверка восстановления**: файл выполняется в чистой базе одной транзакцией; проверяются все таблицы из `migrations/`, `integrity_check`, внешние ключи. Не восстановился — прогон красный, бэкап не сохраняется.
3. **Шифрование** (age, X25519) для публичных ключей из `security/backup-recipients.txt`. В бэкапе Steam ID и ники игроков, а артефакты публичного репозитория может скачать любой залогиненный на GitHub — поэтому только зашифрованным.
4. Артефакт `d1-backup-<id>`: `kollgg-ДАТА.sql.age` + `.sha256`. Открытый SQL на диске раннера удаляется.

Выгрузка на время ненадолго блокирует запросы к базе — поэтому ночью.

**Каждый PR** CI гоняет `npm run backup:selftest`: та же цепочка на локальной D1 с тестовыми данными, включая восстановление в пустую D1 через `wrangler d1 execute --file`. Сломается формат выгрузки — узнаем сразу, а не в день аварии.

## Настройка (один раз)

1. **Ключ (sK8le, на своём компьютере):**
   ```
   npm run backup:keygen
   ```
   Секретный ключ сохранится в `kollgg-backup-key.txt` в домашней папке (внутрь проекта скрипт класть не даст). **Сделай копию** в менеджер паролей или на флешку: потеряешь ключ — все бэкапы превратятся в мусор. Публичный ключ (`age1…`) скрипт напечатает.
2. **Публичный ключ** — в `security/backup-recipients.txt` отдельным PR (его можно показывать всем). Можно несколько ключей, по одному в строке — тогда открыть бэкап сможет любой из владельцев (например, и друг).
3. **Токен Cloudflare (sK8le):** https://dash.cloudflare.com/profile/api-tokens → Create Token → Custom token → право **Account → D1 → Edit** (экспорт в API Cloudflare — операция записи, одного Read может не хватить), ресурс — свой аккаунт. Отдельный токен: не аналитика и не деплой.
4. **Секреты в GitHub (prod-xeinty, нужен Admin):** https://github.com/prod-xeinty/cstactics/settings/secrets/actions → `CF_BACKUP_TOKEN` = токен из п. 3; `CLOUDFLARE_ACCOUNT_ID` (уже есть, если настроены лимиты).
5. Actions → «Бэкап D1» → **Run workflow** → в Summary таблица таблиц и число строк, в Artifacts — файл. Упало с ошибкой авторизации — проверь право токена.

Пока чего-то нет, прогон зелёный и пишет, чего не хватает.

## Восстановление

> Любое восстановление **перезаписывает** данные. Сначала остановись и запиши, что случилось и до какого момента откатываемся.

### А. Откат на момент времени (последние 7 дней) — Time Travel
```
npx wrangler d1 time-travel info kollgg --timestamp=2026-10-25T18:00:00Z
npx wrangler d1 time-travel restore kollgg --timestamp=2026-10-25T18:00:00Z
```
Команда `restore` выведет **закладку предыдущего состояния** — сохрани её: по ней можно отменить сам откат (`--bookmark=…`).

### Б. Из ежедневного бэкапа
1. Actions → «Бэкап D1» → нужный прогон → Artifacts → скачать `d1-backup-…` и распаковать.
2. Проверить целостность: `sha256sum -c kollgg-ДАТА.sql.age.sha256` (на Windows: `certutil -hashfile kollgg-ДАТА.sql.age SHA256` и сравнить вручную).
3. Расшифровать (в папке проекта):
   ```
   npm run backup:decrypt -- kollgg-ДАТА.sql.age C:\Users\<ты>\kollgg-backup-key.txt kollgg-ДАТА.sql
   ```
4. **Восстанавливать в новую базу**, а не поверх старой:
   ```
   npx wrangler d1 create kollgg-restore
   npx wrangler d1 execute kollgg-restore --remote --file kollgg-ДАТА.sql
   npx wrangler d1 execute kollgg-restore --remote --command "SELECT COUNT(*) FROM users"
   ```
5. Если данные верные — вписать `database_id` новой базы в `wrangler.jsonc` (PR), задеплоить, проверить `/api/health`. Старую базу не удалять, пока не убедились, что всё работает.
6. **Удалить расшифрованный `.sql`**: в нём открытые данные игроков. Не коммитить, не пересылать.

### Учения
Раз в месяц: пункт Б целиком на свежем бэкапе (до шага 5 — в базу `kollgg-restore`, потом удалить её: `npx wrangler d1 delete kollgg-restore`). Записать дату в комментарий к #25 / заметку в журнале.

## Персональные данные
Бэкапы содержат Steam ID и ники и лежат на серверах GitHub и Cloudflare за пределами РФ — учесть в политике конфиденциальности (#27). Срок хранения — 30 дней, дальше GitHub удаляет артефакты сам.
