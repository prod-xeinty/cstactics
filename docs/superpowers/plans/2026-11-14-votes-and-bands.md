# Голоса и шкалы оценок (#13)

## Решение

Для опубликованной тактики один игрок хранит один голос (`works` и `easy`, 1–5). Шкала определяется свежим запросом FACEIT при голосовании; при недоступности API голос не меняется. В D1 храним только шкалу голоса и время следующей проверки, не уровень и не эло. Голоса пользователя переводятся в новую шкалу вместе с пересчётом `rating_stats` в одной транзакции D1. Cron обходит игроков с голосами, чья проверка просрочена, небольшими партиями.

## Файлы

- `src/ratings/repository.ts` — атомарная запись голоса, перенос шкалы и выборка агрегатов.
- `src/ratings/refresh.ts` — выбор игроков на проверку и обновление их голосов.
- `src/app/api/tactics/[id]/votes/route.ts` — публичный GET оценок и защищённый POST голоса.
- `src/app/api/auth/me/route.ts` — выдача производного CSRF-токена для клиентского POST.
- `src/platform/types.ts`, `src/platform/cloudflare.ts`, `tests/sqlite-db.ts` — транзакционный `batch`.
- `faceit_profiles.checked_at` и `next_check_at` уже есть в схеме; используем их только как расписание без сохранения профиля.
- `worker/index.ts`, `wrangler.jsonc` — периодический запуск.
- `tests/ratings.test.ts`, `tests/votes-route.test.ts`, `tests/ratings-refresh.test.ts` — поведение и инварианты.
- `docs/api/votes.md` — контракт для фронтенда.
