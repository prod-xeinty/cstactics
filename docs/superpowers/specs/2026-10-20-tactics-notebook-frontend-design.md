# Frontend MVP «Блокнот тактик»

Статус: согласовано
Дата: 2026-10-20  
Визуальная система: `DESIGN.md`

## 1. Цель

Собрать первый рабочий frontend КОЛЛ.GG, на котором пользователь без входа может выбрать параметры команды, получить подходящую тактику Dust2 и открыть полный разбор. Интерфейс реализуется только в светлой системе «Блокнот тактик».

## 2. Границы первого этапа

В этап входят:

1. Главная с рекомендацией и быстрыми фильтрами.
2. Быстрый экран колла для freeze time.
3. Детальная страница одной тактики.
4. Локальные типизированные демо-данные.
5. Адаптивная вёрстка и базовая доступность.
6. Рабочая навигация между тремя экранами.

Не входят: Steam, FACEIT API, голосование, D1, R2, отправка тактики, модерация и настоящий быстрый режим раунда. Для них оставляются понятные интерфейсы, но не имитируется серверное поведение.

## 3. Техническая основа

- Next.js App Router, React и TypeScript.
- Обычные серверные компоненты по умолчанию; клиентские компоненты только для фильтров, поиска и интерактивных состояний.
- CSS Modules и глобальные CSS-переменные из `DESIGN.md`.
- Типы тактик отделены от демо-данных.
- Данные читаются через небольшой интерфейс репозитория, чтобы позже заменить fixtures на D1 без переделки компонентов.
- Изображения и схемы лежат в `public/`; сложная графика не рисуется div-элементами.

## 4. Маршруты

### `/`

Главная показывает:

- шапку;
- заголовок «План на следующий раунд»;
- фильтры карты, стороны, состава и FACEIT-группы;
- одну рекомендованную тактику;
- содержательную схему;
- короткий список альтернатив;
- переход в каталог и детальную страницу.

Изменение фильтров обновляет рекомендацию локально и отражается в URL.

### `/call/[slug]`

Экран показывает одну короткую команду, пять пронумерованных ролей, текущий шаг и следующий шаг. По умолчанию он не требует авторизации и использует те же данные тактики, что и подробная страница. Из экрана можно перейти к следующему шагу, запросить другой колл или вернуться к полному плану.

### `/tactics/[slug]`

Детальная страница показывает:

- заголовок и метаданные;
- быстрый колл;
- схему маршрута;
- до четырёх шагов;
- роли 1–5;
- список утилити;
- запасной план;
- статус проверки и версию игры.

Неизвестный slug возвращает стандартную страницу 404.

## 5. Компоненты

- `SiteHeader` — логотип, навигация, поиск, мобильное меню.
- `TacticFilters` — управляемые фильтры и сброс.
- `FeaturedTactic` — рекомендация на главной.
- `TacticList` и `TacticListItem` — альтернативы на главной; позже переиспользуются в каталоге.
- `TacticMap` — изображение схемы с доступным текстовым описанием.
- `TacticMeta` — карта, сторона, состав, FACEIT, сложность, длительность.
- `RoundSteps` — последовательность действий.
- `RoleAssignments` — роли по номерам.
- `QuickCallMode` — крупная команда, активный шаг и управление сценарием.
- `UtilityChecklist` — гранаты и триггеры.
- `PatchNotice` — закрываемое предупреждение, состояние в `localStorage`.
- `EmptyState` и `ErrorState` — единые состояния.

## 6. Данные

Fixture соответствует типу `Tactic` из `AGENTS.md`. Для первого экрана достаточно 6–8 тактик Dust2 с явно помеченными демо-оценками. Используются только коллауты из словарика проекта.

Функции чтения:

```ts
interface TacticsRepository {
  list(filters: TacticFilters): Promise<TacticSummary[]>;
  featured(filters: TacticFilters): Promise<TacticSummary | null>;
  bySlug(slug: string): Promise<Tactic | null>;
}
```

Компоненты страниц не импортируют fixture напрямую.

## 7. Состояния и ошибки

- До загрузки резервируется место под основной контент.
- Пустой результат предлагает сбросить фильтры.
- Ошибка чтения показывает повтор действия без потери выбранных фильтров.
- Закрытие предупреждения о патче хранится локально с ключом версии патча.
- Пользовательский текст никогда не рендерится через `dangerouslySetInnerHTML`.

## 8. Адаптивность

- Desktop: двухколоночная главная и детальная страница.
- Tablet: схема и текст делят ширину приблизительно поровну, вторичные данные переносятся ниже.
- Mobile: одна колонка; сначала колл и действие, затем схема, шаги и роли.
- Интерактивные элементы не меньше 44 px.
- Длинные названия переносятся, а не обрезаются.

## 9. Тестирование

### Unit

- фильтрация и сортировка fixtures;
- выбор рекомендации;
- форматирование метаданных;
- ключ закрытого предупреждения о патче.

### Component

- управление фильтрами с клавиатуры;
- состояния списка: данные, пусто, ошибка;
- мобильное меню;
- доступные названия интерактивных элементов.

### E2E

- главная → изменение фильтров → открытие рекомендации;
- главная → быстрый колл → переключение шагов → полный разбор;
- главная → детальная страница;
- закрытие и повторное скрытие предупреждения о патче;
- viewport 390 px и клавиатурная навигация.

### Visual QA

- сравнение главной, быстрого колла и детальной страницы с утверждёнными макетами при 1440 × 1024;
- отдельная проверка 390 × 844;
- обязательное исправление визуальных проблем уровней P0–P2 до передачи.

## 10. Критерии готовности

1. Три маршрута доступны и связаны навигацией.
2. Фильтры и URL остаются синхронизированы.
3. На каждой странице есть loading, empty и error состояние там, где применимо.
4. Интерфейс соответствует `DESIGN.md` и не содержит бордовых элементов.
5. Проходят lint, typecheck, unit-тесты, production build и Playwright.
6. `design-qa.md` содержит `final result: passed`.
