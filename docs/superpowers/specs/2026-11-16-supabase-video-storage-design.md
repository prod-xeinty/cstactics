# Supabase Storage для видео — дизайн

## Зачем

Добавить бесплатную загрузку видео из анкеты без привязки карты. Видео игрока должно оставаться приватным до модерации, а опубликованные байты должны совпадать с теми, которые проверил сервер.

## Цели и ограничения

- Принимать только MP4 и WebM размером не больше 10 МБ.
- Проверять на сервере размер, заявленный MIME, сигнатуру файла и SHA-256.
- Не отдавать непроверенное видео публично.
- Не допускать перезаписи проверенного объекта до публикации.
- Не класть Supabase service role key в клиент, репозиторий или логи.
- Сохранить платформенный `ObjectStorage`, чтобы хранилище можно было заменить.

Не делаем в этой задаче транскодирование, превью, возобновляемую загрузку и очистку старых отклонённых файлов по расписанию.

## Рассмотренные подходы

1. **Серверная загрузка в Supabase Storage — выбран.** Worker принимает файл до 10 МБ, полностью проверяет его и пишет в приватный бакет под случайным ключом. Это самый короткий безопасный путь для MVP и не оставляет клиенту URL, пригодный для перезаписи.
2. **Подписанная прямая загрузка с подтверждением.** Экономит трафик Worker, но требует отдельного протокола create/confirm, защиты от зависших загрузок и повторной проверки объекта. Для текущего лимита 10 МБ сложность не окупается.
3. **Cloudflare R2.** Лучше встроен в Worker, но активация R2 требует платёжного профиля, которого у владельца проекта нет.

## Поток данных

1. `POST /api/tactics` проверяет сессию, CSRF, rate limit и поля анкеты.
2. Если есть видео, сервер читает не больше допустимого лимита, проверяет MIME и magic bytes (`ftyp` для MP4, EBML для WebM), считает SHA-256 и пишет объект в приватный бакет с запретом перезаписи.
3. Тактика и строка `tactic_media` создаются со статусами `pending` и `verified`; в JSON тактики сохраняется внутренний URL `/media/<media-id>`.
4. При публикации сервер повторно читает приватный объект, сверяет фактический размер, MIME, сигнатуру и checksum, затем пишет те же байты под новый случайный ключ в публичный бакет с запретом перезаписи.
5. Только после успешной копии строка медиа получает `published`, а тактика атомарно переходит в `published`. Маршрут `/media/<media-id>` отдаёт только опубликованное медиа опубликованной тактики.

Если копия в хранилище создана, а запись в D1 не удалась, объект остаётся недоступным через приложение; повторная попытка использует новый ключ. После успешной публикации приватная копия удаляется в режиме best effort.

## Конфигурация

- Публичная переменная Worker: `SUPABASE_URL=https://inqwhzfhxkxaznckypdw.supabase.co`.
- Серверный секрет: `SUPABASE_SERVICE_ROLE_KEY` через `.dev.vars` или `wrangler secret put`.
- Бакеты: `tactic-videos-private` (private) и `tactic-videos-public` (public).

Supabase Free ограничивает хранилище и исходящий трафик; при приближении к квоте загрузка должна завершаться понятной ошибкой, а не делать тактику опубликованной частично.
